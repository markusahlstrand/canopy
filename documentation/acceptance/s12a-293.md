Parent: [#78](https://github.com/markusahlstrand/canopy/issues/78).
## Correction

Invitation, removal, and withdrawal responses are ignored after their dialog visit ends. New visits reset busy state and cannot display an invitation link or error from the old visit.

## Complete shell browser coverage

On 8 October 2026, all 10 browser cases and all 524 UI tests passed; worker/app and browser-test TypeScript checks passed. The PR includes six desktop/mobile Chromium acceptance cases for the shell, in addition to the four inherited drive cases. The built SPA uses real OIDC, SQLite Durable Objects, and R2. Only the external control plane is replaced by a local fixture: it consumes the real durable space-creation intent and calls the platform's normal configure/provision/settle routes. This does not establish hosted control-plane behavior.

| Checklist | Browser verification |
|---|---|
| Rail/mobile navigation and current space | Long display names stay within the viewport; the picker and current-space context agree |
| Create/switch space | The UI creates a durable intent, waits for provisioning, and opens the new empty space; a folder written there is absent from the previous space |
| Style/manage space | Name, icon, and color changes persist across reload and agree with the selected space's API settings |
| Members | Viewer invitation is created in the selected space and withdrawal removes it; previous-visit mutation responses cannot change a reopened dialog |
| Failure/empty states | Failed space-list refresh retains context and offers Retry; a no-match search retains the current space |
| Offline recovery | Native browser disconnection keeps saved context, disables upload/create-space, and Refresh recovers after reconnect |
| Accepted members | A real viewer and a real editor accept invitations in a created space (separate browser contexts); the owner's roster lists them as people with Remove, not as open invitations; neither recipient is offered Manage members, Space settings or Create space, and neither overflows the viewport (`e2e/shell-members.spec.ts`) |
| Account identity | The menu has an accessible name and displays the verified OIDC name rather than the internal principal ID |
