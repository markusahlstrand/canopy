# S12a #291: Previews and text editing

Parent: [#78](https://github.com/markusahlstrand/canopy/issues/78).
## Correction

Failed metadata, text body, version history, and extraction reads now show a retry action instead of an indefinite loading or empty-content state.

## Browser acceptance evidence

On 8 October 2026, all eight preview acceptance cases passed in desktop Chromium and mobile Chromium (Pixel 7), using the production SPA, real OIDC login, SQLite Durable Objects, and R2 in a disposable install:

| Checklist | Result |
|---|---|
| Text, image, PDF and installed viewer | Pass; rendered image bytes decode, PDF has a usable viewport, installed Image Viewer receives the uploaded bytes in its sandbox, unsupported binary has a download fallback |
| Details and versions identify the selected file | Pass; a delayed previous-file response cannot replace the next file's details/history |
| Text save and version creation | Pass; UI save creates a third historical version with one current version |
| Conflict rejection preserves draft | Pass; a second browser tab uploads a replacement, the first tab's save is refused, and its complete draft survives until explicit discard/reload |
| Failed reads and retries | Pass; metadata, immutable text-content and history transport failures each recover through Retry preview |

Tests inject transport faults or delays only in the failure cases. Successful reads/writes use the real service. PDF embedded rendering varies by browser; the test verifies the object viewport and the built-in download fallback remains available rather than claiming PDF raster output.

```sh
pnpm test:e2e
pnpm typecheck:e2e
pnpm --filter @canopy/drive-vertical typecheck
pnpm --filter @canopy/drive-vertical exec vitest run --project app preview-retry preview-history preview-media text-editor
```

The shared drive suite has four additional browser cases. PR #320 supplies the harness; this PR adds the full preview acceptance coverage and retry fixes.
