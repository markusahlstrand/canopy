# S12a #298: Offline folders and files

Parent: [#78](https://github.com/markusahlstrand/canopy/issues/78). Also covers #302's folder-control and recursive-sync slice.

## Behavior and corrections

Every offline-content transaction immediately observes its completion rejection, so a rejected write does not also produce an unhandled transaction rejection. Rapid online edits now retain a trailing refresh instead of being skipped inside the throttle window. Background walks update the visible syncing/partial/ready state as they progress and surface failures even if full storage also rejects persisting the failure status. An online API or content refusal clears native bytes and pins and hides cached previews even when membership is revoked while the tab remains open. A captured login epoch prevents a delayed refusal from clearing a newer login’s cache; initial authentication/claim requests retain their existing recovery path.

## Real-browser evidence

The browser suite uses the built SPA, normal OIDC owner/recipient logins, actual local Worker/SQLite/R2 and native Chromium IndexedDB. It uses isolated synthetic data and no production browser profile. Desktop and Pixel 7 projects cover:

| Acceptance | Browser evidence |
| --- | --- |
| Recursive pagination and progress | 52 parent files plus a nested file; one immutable download fails, the pin stays partial, and retry saves all 53 versions |
| Offline preview/download | Native network-offline mode, saved version/time, byte-correct download, disabled upload/mutations, and an explicit uncached-file explanation |
| Overlapping pins | Unpin parent retains the nested pin's bytes; unpin nested removes the final bytes |
| Online reconciliation | Rename, new version, added file and trash are reflected in native rows without manually repinning; superseded bytes are pruned |
| Revocation and logout | Real member removal plus a refused preview metadata request clears recipient bytes and pins; signing out in a second tab clears pins/bytes and hides an open saved preview |
| Principal/in-flight isolation | Replace the synthetic authenticated principal during a held download; earlier pins disappear and the late response cannot recreate its bytes |
| Native quota | A small pre-existing copy survives Chromium's actual quota rejection for a 200 KB incompressible fixture; retry succeeds after resetting the origin override; no unhandled page error |
| Oversized stream | Native Fetch decodes a compressed HTTP fixture beyond 20 MB; the streaming limit rejects it, the pin stays incomplete, and a real-byte retry succeeds |

The quota test waits for Chromium's native 30-second bucket allowance to expire; it does not fill device storage. This allowance is described in [Chromium's bucket implementation](https://chromium.googlesource.com/chromium/src/+/1c9524c5d3627044b0cf0a0b679978e82b702279/content/browser/indexed_db/instance/bucket_context.h). The oversized response, transport failure and held requests are explicit fault injection; accepted retries and role changes use the real APIs.
