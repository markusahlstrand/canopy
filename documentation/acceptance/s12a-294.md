# S12a #294: Folder sharing

Parent: [#78](https://github.com/markusahlstrand/canopy/issues/78).
## Implementation and complete browser coverage

The real recipient workflows uncovered and corrected three gaps:

- Invitations minted in a switched space now include that space's registered slug. OIDC sign-in preserves the destination even when the link contains no folder.
- Folder-grant removal and downgrade now send the generated DELETE route's declared input as query parameters; the previous JSON body was ignored and returned HTTP 400.
- The dialog distinguishes direct folder grants from inherited space roles. Removing a folder grant does not imply that an editor or owner loses their space-wide permissions.

Adding shares remains unavailable while either the current grants or roster cannot be read, and Retry restores it after a successful read.

On 8 October 2026, all six sharing browser cases passed across desktop Chromium and mobile Chromium (Pixel 7), with separate OIDC-authenticated owner/viewer/editor contexts:

| Checklist | Result |
|---|---|
| Invite viewer/editor to the selected space | Pass; new recipients redeem the correct space's links after real OIDC sign-in |
| Recipient permissions | Viewer can read but cannot edit text; editor saves a new version |
| Folder link and access management | Recipient opens the stable folder link; edit/share grant, downgrade, and removal take effect after revisiting the link |
| Remove a member | Recipient's existing authenticated session receives 401 for file content after removal |
| Cross-space Shared with me | A direct grant from another space opens that space and file; revocation removes it from Shared with me |
| Failed access reads | Failed roster disables adding shares and Retry restores it |

The built SPA, identity binding, roles/grants, Durable Objects, and attachments are real. The inherited harness emulates only the external control plane's consumption of real creation intents. Only the failed-roster case injects a transport error. Focused sharing/navigation/drive component coverage passed 135 tests; the full app suite passed 526 tests in 89 files. Worker/app and browser-test TypeScript checks passed.

```sh
pnpm test:e2e
pnpm typecheck:e2e
pnpm --filter @canopy/drive-vertical typecheck
pnpm --filter @canopy/drive-vertical exec vitest run --project app
```

Sharing remains folder-only by the decision in #296. Membership reads the whole space; narrowed folder grants add editing/sharing. WebDAV #14 remains separate.
