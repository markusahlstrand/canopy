# S12a #292: Palette and results search

Parent: [#78](https://github.com/markusahlstrand/canopy/issues/78). Also tracks #22; the built-in search decision is documented in `documentation/03-how-plugins-work.md`.

## Behavior and corrections

Search remains a built-in capability. Failed results refreshes clear earlier hits and selection and offer a retry of the current query. Metadata snippets now include both matching description and label context instead of hiding the matching label whenever the description also matches.

## Real-browser evidence

On 9 October 2026, `e2e/search.spec.ts` passed all four cases in isolated Chromium desktop and mobile projects against the built SPA, real local Worker, SQLite scope host and normal OIDC owner/recipient accounts. Only the single transport failure is injected; search results, extracted text, metadata, roles and installed plugins use the actual APIs.

| Acceptance | Evidence |
| --- | --- |
| Name, extracted body, description and label matches | Real uploads and edited metadata; results, match filters and palette context checked |
| Open the correct result | Pointer opens name/metadata hits; keyboard selects and opens the body hit |
| Refused membership | Separate recipient browser cannot find the private marker, see its space or fetch its search/content routes (401) |
| Built-in search independence | Installed and built-in image viewers disabled; both search entry points still return the marker |
| Failure recovery | Failed refresh clears stale hits and selection; retry restores the three real matches |

The search regression and full scope-drive suite passed 689 tests in 12 files. The focused app suite passed 126 tests. Worker, app and browser-suite TypeScript checks passed.
