# S12a #299: WebDAV and Shared with me mounts on the drive vertical

Follow-up to [#14](https://github.com/markusahlstrand/canopy/issues/14) and [#78](https://github.com/markusahlstrand/canopy/issues/78). The legacy `apps/api` WebDAV endpoint and its tests were migration inputs only; this is a new implementation on the vertical's scope operations, attachments and identity model.

## Decisions

| Issue scope | Decision |
| --- | --- |
| Authentication | HTTP Basic with per-login **app passwords**. They are minted in the account menu, shown once, and stored as SHA-256 hashes in the tenant identity DO, keyed by OIDC subject (kernel-design §7.3: a per-login fact, not a per-scope one). Each login can hold up to 20, and each can be revoked individually. The user name is ignored and only logged on failure. |
| Port to scope-local operations | Every request resolves the subject to a principal in each space through the identity rows a browser session uses, then calls scope operations and attachments as that principal. The retired shared-database store is not involved. Two read operations were added to `@canopy/scope-drive`: `drive/file-by-name` and `drive/list-file-entries`. Neither has an HTTP route. |
| Spaces and direct grants with collision-safe names | `/dav/<Space>/…` for each space the login can enter. A space whose name is shared with another space gets ` (<slug>)` appended. `/dav/Shared with me/<folder> — <space> [<key>]/…` holds direct grants; the key comes from the space and folder id, so a mount's URL survives a rename. A space named "Shared with me" keeps that name, and the virtual collection becomes "Shared with me (Canopy 1)". |
| Viewer/editor rights and revocation | Enforced by the kernel on every call. The namespace is rebuilt per request, so a withdrawn grant or a removed membership makes previously known URLs answer 404. A revoked password answers 401. |
| Methods and write semantics | `PUT` adds a version (25 MB cap). `DELETE` of a file moves it to Trash. A trashed name stays reserved, so reusing it answers 409 with an explanation. `MOVE`/`COPY` onto an existing file add a version to it, which supports save-by-rename editors. `MKCOL`, `PROPFIND` (depth 0/1) and `PROPPATCH` (accepted but not stored) are supported. `LOCK`/`UNLOCK` hand out tokens without enforcing locks, so Finder mounts read-write. |
| Unsupported operations, kept explicit | `DELETE` of a folder, `COPY` of a folder, and `MOVE` across spaces each answer 403 with a reason. `GET` on a collection answers 405. Range requests return the whole file. |

All bytes are served with `Content-Security-Policy: sandbox`, and active types are served as downloads, because `/dav` shares the app's origin. Hosted installs route `/dav` and `/dav/*` to the worker through `runtimeNeeds.assets.runWorkerFirst`; the local acceptance server and the Vite proxy do the same.

## Local evidence (10 October 2026)

| Case | Evidence |
| --- | --- |
| App-password storage | `apps/drive-vertical/test/app-passwords.test.ts`: subject-scoped list and revoke, hash lookup, last-used throttling, the per-login cap, secret format |
| Protocol over real scopes | `apps/drive-vertical/test/webdav.test.ts` runs 14 cases against `SqliteScopeHost` (real permissions and stored bytes): auth, OPTIONS, the root listing per login, MKCOL/PUT/GET/PROPFIND, versions, junk files, rename/move/overwrite-by-version, copy across spaces, refused cross-space moves and folder deletes, Trash name reuse, dot-segment and encoded-separator refusal, a viewer's read-only access, a grant mount that writes only in its subtree and survives a rename, revocation closing a known mount URL, and space/virtual-collection name collisions. A mutation of the mount lookup fails the suite. |
| Name reads | `packages/scope-drive/test/name-reads.test.ts`, plus the entity-check conformance kit for the two new operations |
| Dialog | `app/src/app-passwords-dialog.test.tsx`: address, one-time secret, revoke, refused creation, retry |
| Real worker and browser | `e2e/webdav.spec.ts` on desktop Chromium and Pixel 7 against `scripts/acceptance-server.mjs` (built SPA, OIDC owner and recipient logins, Worker, SQLite, R2). The owner mints a password in the UI; a WebDAV client sends Basic auth only. It covers PUT/GET in both directions with the browser, MKCOL, MOVE, refused folder DELETE, a viewer refused a write, an edit grant mounted under Shared with me and writable only there, grant withdrawal and member removal returning 404 at known URLs, and password revocation returning 401. |
